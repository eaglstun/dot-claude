# bass.md format

Bass chart as **per-section tablature**: one document the player reads top to bottom
during the song. It follows `lead.md` exactly — same sections in the same order, same
bars — but each chord row is rendered as an actual bass tab (one column per bar, the
chord's bass note at its go-to low-neck fret) instead of a chord grid. There is no
single Positions table up top: the notes live in each section, right where they're
played. Lyrics ride under each staff; bass-specific info rides inline.

Generated by `scripts/gen_chart.py --only bass` from the song's `chart.py` +
`lead.md`. Do not hand-edit the output — put hand-written content in `chart.py`'s
`BASS_CUES` and regenerate.

````markdown
# Song Title — Bass

Standard tuning, low→high: **E A D G**. Each section below is bass tablature — one column per bar, read left to right. Play the chord root (on slash chords `X/Y`, the slash note `Y`) at the fret shown; frets are the go-to low-neck position. Inline `bass:` and feel cues flag anything that isn't a plain root.
````

## Format rules

- Title: `# Song Title — Bass`
- Preamble: the standard tuning/notation paragraph (one source line — flow-file PDFs
  render soft breaks for real)
- **No** `## Positions` table, no per-chord tab library, no quick-reference table —
  the per-section tabs carry every position
- One `## Section — bars X-Y` header per `lead.md` section, in `lead.md` order, header
  text copied verbatim
- **Tab block** — one fenced ` ``` ` code block per chord-bearing `lead.md` row (the
  fence keeps it monospace in the PDF). Five lines:
  - a **label line** of chord names, one per bar, in playing order (duplicate bars
    repeated), aligned over their columns
  - four **staff lines** `G` / `D` / `A` / `E` (high→low), each `L |…|`. For each bar,
    the chord's **bass target** (the slash bass on `X/Y`, else the root) is written at
    its **go-to low-neck fret** — the lowest fret for that note on the E or A string —
    on the matching string; every other cell is `-`
- **Chordless bars** (rest / pad / count-in rows in `lead.md`) render as an italic note
  instead of a tab: the row's `_(…)_` / `*(…)*` annotation if it has one, else
  `_(tacet)_`
- **Lyrics**: the `lead.md` lyric line for a row is printed italic right under that
  row's tab (`_…_`), verbatim — no added quotes
- **Inline cues**, italic, after the tab (and lyric) for the row:
  - **Auto slash cues** — any row with slash chords gets `_bass: ..._`:
    `_bass: F♯ (E-2) throughout_` when every chord in the row targets the same slash
    note, otherwise `_bass: A7/D → D (A-5) · C#m/A → A (A-open)_` per chord. Repeated
    identical cues within a section are emitted once
  - **Hand feel cues** — from `chart.py`'s `BASS_CUES` dict: rendered as
    `_<key> — <text>_` under the FIRST `lead.md` row matching the key. Keys are a chord
    name (`"Dmaj7"`) or a `·`-joined chord sequence (`"A7/D · F#7sus4/D"`) that must
    appear, in order, in a row. A row with a hand cue skips its auto slash cue (the hand
    cue covers it). A key matching no row is a generation error, not a silent drop
- **Trailing annotations** on a chord row (e.g. `_(fade out)_` after the last chord)
  are preserved as an italic note after the tab
- No tuning/fret reference table in the file (lives in `references/tuning.md`)

## BASS_CUES authoring (in the song's chart.py)

```python
BASS_CUES = {
    "Dmaj7": "Lush landing after the build. Root on D, but give it room.",
    "A7/D · F#7sus4/D": "Stay on D through the whole vamp while the chords "
                        "above you shift.",
}
```

Write cues for: slash chords where the note choice needs a why, walkups/walkdowns the
bass leads, pedal-point vamps, and feel guidance (space, tension, resolution targets).
Root-following rows need no cue — silence means "play the root".
