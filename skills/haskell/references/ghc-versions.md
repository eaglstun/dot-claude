# GHC versions, `base`, and migrations

Source:

- https://downloads.haskell.org/ghc/latest/docs/users_guide/
- https://gitlab.haskell.org/ghc/ghc/-/wikis/migration
- https://hackage.haskell.org/package/base
- https://www.stackage.org/
- https://github.com/haskell/core-libraries-committee

**Verify the current release before quoting one.** `ghcup list` and the GHC
release notes are authoritative; this page records the changes that matter for
reading and porting code, not a live release feed.

## 1. `base` ↔ GHC map

`base`'s version is the reliable way to CPP-guard code, because it's what
`build-depends` sees.

| GHC  | `base` | Notable                                                                             |
| ---- | ------ | ----------------------------------------------------------------------------------- |
| 8.0  | 4.9    | `Semigroup` in base, `TypeApplications`, `DuplicateRecordFields`                    |
| 8.2  | 4.10   | `DerivingStrategies`, `Type` instead of `*`                                         |
| 8.4  | 4.11   | **`Semigroup` becomes a superclass of `Monoid`**                                    |
| 8.6  | 4.12   | **`MonadFail` desugaring**, `DerivingVia`, `QuantifiedConstraints`                  |
| 8.8  | 4.13   | `fail` removed from `Monad`, `StarIsType`                                           |
| 8.10 | 4.14   | `StandaloneKindSignatures`, `UnliftedNewtypes`                                      |
| 9.0  | 4.15   | **Simplified subsumption**, `LinearTypes`, `hGetContents'`                          |
| 9.2  | 4.16   | **`GHC2021`**, `OverloadedRecordDot`, `NoFieldSelectors`                            |
| 9.4  | 4.17   | `\cases`, `-fprof-late`, `-hi` info-table profiling                                 |
| 9.6  | 4.18   | JS and WASM backends, `Data.List.!?`                                                |
| 9.8  | 4.19   | **`head`/`tail` get `x-partial` warnings**, `unsnoc`, `TypeAbstractions`            |
| 9.10 | 4.20   | **`GHC2024`**, `foldl'` in `Prelude`, `RequiredTypeArguments`, exception backtraces |
| 9.12 | 4.21   | `NamedDefaults`, `MultilineStrings`, further backtrace work                         |

Newer releases exist beyond this table; check `ghcup list` rather than assuming.
Stackage LTS trails the newest GHC by a release or two — that's usually the
version to target for an application.

## 2. The migrations that actually break code

**Semigroup/Monoid (GHC 8.4).** `instance Monoid X` now requires
`instance Semigroup X` with `(<>)`. Every hand-written `Monoid` from before 8.4
needs splitting:

```haskell
instance Semigroup X where (<>)   = ...
instance Monoid    X where mempty = ...     -- mappend = (<>) is the default
```

**MonadFail (GHC 8.6/8.8).** A failable pattern in a `do` bind now needs
`MonadFail m`, and `fail` is gone from `Monad`. Code doing
`Just x <- pure (lookup k m)` in a non-`MonadFail` monad stops compiling. Fix
with an explicit `case`, or `maybe (throwError e) pure`.

**Simplified subsumption (GHC 9.0).** GHC no longer silently eta-expands to
match a more-polymorphic type. The symptom is a type error on code that looks
fine:

```haskell
f :: (forall a. a -> a) -> Int
g :: Int
g = f id            -- fine
h = map f fs        -- may now need \x -> f x
```

Fix: eta-expand manually (`\x -> ...`), or `-XDeepSubsumption` (GHC 9.2+) as a
transitional flag.

**`head`/`tail` warnings (GHC 9.8).** `Data.List.head`/`tail` carry a `WARNING`
pragma. With `-Werror` this breaks the build. That's a feature — fix the call
sites (see `syntax-and-idioms.md` §7) — but you can silence it per-module with
`{-# OPTIONS_GHC -Wno-x-partial #-}` while you migrate.

**`GHC2024` / `MonoLocalBinds`.** Opting into `GHC2024` (or enabling
`TypeFamilies`/`GADTs`) turns on `MonoLocalBinds`, which stops generalizing
local bindings. Previously-fine `where` helpers used at two types now fail. Fix
by adding a type signature to the local binding.

**`Data.List` monomorphism.** In the `Foldable`-generalized world,
`Data.List.length` etc. are the list-specific ones; some proposals have moved
these around. Import explicitly rather than relying on the `Prelude` export.

## 3. CPP version guards

```haskell
{-# LANGUAGE CPP #-}
#if MIN_VERSION_base(4,18,0)
import Data.List (unsnoc)
#else
unsnoc xs = if null xs then Nothing else Just (init xs, last xs)
#endif

#if __GLASGOW_HASKELL__ >= 906
...
#endif
```

Guard on **`MIN_VERSION_<pkg>`** (generated by cabal) rather than
`__GLASGOW_HASKELL__` where possible — it's the dependency you actually care
about, and it works when someone uses a newer `base` on an older GHC.

Every `#if` is a configuration nobody tests. Keep the number small, and put the
compatibility shims in one `Compat` module rather than scattering them.

## 4. Choosing a baseline

- **Application**: whatever the current Stackage LTS uses, or one release
  behind the newest GHC. You control the deployment, so there's no reason to
  support a range.
- **Library on Hackage**: the three most recent GHC major releases is the
  common courtesy standard. `base >=4.16 && <5` style bounds, and a CI matrix
  that actually builds all of them (`haskell-actions/setup` with a matrix).
- **`Cabal`'s `tested-with:`** field documents what you've verified.

The `base >= x && < 5` upper bound is a convention: `base` will never hit 5, so
it's an "unbounded but explicit" bound that keeps the solver honest.

## 5. Deprecation and the CLC

Changes to `base` go through the **Core Libraries Committee** proposal process
(github.com/haskell/core-libraries-committee); language changes go through
**GHC proposals** (github.com/ghc-proposals/ghc-proposals). Both are public and
searchable — when you want to know _why_ something changed, or whether a change
is coming, those two repos are the primary source.

`-Wcompat` turns on warnings for changes scheduled in future releases. Turn it
on in CI; it converts a future breakage into a present warning.

## 6. Upgrading a project — the order that hurts least

1. Read the release notes' "Migration" section for each version you're skipping.
2. Bump GHC via `ghcup`, and HLS to match.
3. `cabal build` and fix compile errors before touching dependency versions.
4. Relax upper bounds (`allow-newer` temporarily) to see what the solver wants.
5. Re-freeze (`cabal freeze`) and run the tests.
6. Turn `-Wcompat` warnings back to zero before calling it done.

Skipping two major GHC versions at once roughly triples the work of doing them
one at a time; the errors interact.

## Gotchas

- **Don't quote a "latest GHC" from memory.** `ghcup list` or the release notes.
- **`base` version, not GHC version, is what `build-depends` constrains** — and
  what `MIN_VERSION_base` guards.
- **Stackage LTS is behind the newest GHC**, often by two releases. A library's
  newest features may not be reachable from your snapshot.
- **`GHC2024` is a migration**, mainly because of `MonoLocalBinds`.
- **Enabling `TypeFamilies` or `GADTs` enables `MonoLocalBinds` too**, breaking
  unrelated local bindings in the same module.
- **`-Werror` plus a GHC upgrade means new warnings break the build.** Keep
  `-Werror` in CI where you can see and fix it, not in the default flags.
- **CPP guards untested paths.** If you `#if` it, build it in CI.
- **`-XDeepSubsumption` is a transitional crutch**, not a fix — the eta-expansion
  it hides can also hide a real type error.
